Read `STATE.md` first, then `docs/HANDOFF.md`.

## Mission

A clean-room, open-source, MIT-licensed, local-first workspace application:
nested pages, a block editor, and page-backed databases. Every line of code,
icon, word and name is original or openly licensed.

## Legal rules (non-negotiable, short form)

1. **Never copy another product's code.** Analysis informs behaviour; all code
   is our own. Treat recovered material as a specification of observable
   behaviour and rewrite it in your own words.
2. **Never copy another product's assets.** No logos, wordmarks, app icons,
   illustrations, template galleries, emoji artwork, icon files, bundled fonts,
   sounds, or distinctive long UI strings. Short functional labels ("Search",
   "Trash", "Favorites") are ordinary words and are fine.
3. **Never use another vendor's name or marks** in the product name, title,
   installer, package id, URL or bundle id.
4. **No service impersonation.** Never contact another vendor's servers from the
   product. Never reuse tokens, cookies or session state. The product runs
   fully offline. Third-party compatibility, if any, comes from **export files
   the user supplies** and **public documented formats** only.
5. **No circumvention.** Do not bypass licensing, authentication, DRM, signing,
   update or integrity checks. Do not patch third-party binaries. Do not
   redistribute them.
6. **Privacy.** Never read, copy, log or ship real personal account data. Use
   synthetic samples in every test.
7. **Dependencies** must be MIT, BSD, ISC, Apache-2.0 or MPL-2.0 as an
   unmodified dependency. No GPL, AGPL or commercial licence. Every dependency is
   recorded in `THIRD_PARTY_NOTICES.md`.
8. If an instruction would force you to break rules 1–7: stop, explain, offer
   the clean-room alternative.

## Layers

`L0 geom` < `L1 model/text/db-engine` < `L2 storage/formats` < `L3 commands`
< `L4 automation` < `L5 ui-kit/editor-ui` < `L6 app-ui` < `L7 apps`

A package may import only from lower layers. **A relative import may not escape
its own package directory.** `node tools/xtask/layering.mjs` enforces both and is
part of CI. Verified working: it catches an injected `L0 -> L1` import.

## Commands

```bash
npm install --ignore-scripts          # no native build step is required
node tools/xtask/ci.mjs               # layering, attribution, typecheck, unit, parity
node apps/cli/bin/ow.mjs help         # the CLI / agent interface
npx vitest run                        # unit and scenario tests only
node tools/xtask/parity-report.mjs    # regenerate the ledger reports
```

The CLI runs from TypeScript source. There is no build step, so what the tests
exercise is what the CLI runs.

## Definition of done (per slice)

1. Code merged; typecheck and tests green.
2. Ledger rows updated with a proof path that exists on disk.
3. At least one headless scenario passes through the command registry, and where
   UI is involved a Playwright test passes.
4. A screenshot generated by the app's own harness is saved under `docs/images/`.
5. `STATE.md` updated; commit made.
6. No new warning-level logs in the standard scenario.

## Honesty

Use these four words precisely:

- **implemented** — code exists and compiles.
- **working** — it was run and the result seen.
- **tested** — an automated test exists and was seen passing.
- **verified against the reference** — compared with observed or documented
  behaviour.

Never write "all tests pass" without running the suite in the same session and
quoting the summary line. Never write "the installer works" without having
installed it, or without saying plainly that it was only built. Show failing
output when something fails. A false "done" is the worst thing we can produce.

## Style

TypeScript strict, including `noUncheckedIndexedAccess`. Small files; no file
over roughly 600 lines without a written reason. No global CSS monolith.
Colours and spacing come from design tokens only.

**No UI code may mutate the model except through a command.** The command
registry is the only door.

## Never

- Add a dependency without recording it in `THIRD_PARTY_NOTICES.md`.
- Add an asset without recording it in `ATTRIBUTION.md`.
- Read real user data.
- Commit anything under `analysis/raw/` (it holds the reference build).
- Claim a feature is done with no proof path that resolves on disk. The parity
  generator downgrades such rows automatically.
