# Known gaps

An honest list of what is not built, what is built but unproven, and what is
built on an unverified assumption. Grouped by how much it matters.

Numbers come from `parity/ledger.csv` via `node tools/xtask/parity-report.mjs`.
Latest generated figures:

- Catalogued features: **172**
- Weighted parity across all tiers: **88.3%**
- Tier 1: **98%** (134/137) · Tier 2: **32%** (11/34) · DONE 145 · TODO 27
- Sources: 169 rows `HINT` (hypotheses from public documentation), 3 `operator-requirement`

## 1. The database layer cannot compute

The largest functional gap. Missing:

- **No formula property** (`DB-PROP-0020`) and **no formula language**
  (`DB-FORM-0050`). There is no expression parser, so no row can hold a
  computed value.
- **No relation or rollup** (`DB-PROP-0021`). Two databases cannot refer to each
  other, and one cannot aggregate another.
- **No nested filter groups** (`DB-FILT-0040`). The filter engine parses nested
  `AND`/`OR` groups correctly, but no command or control reaches it, so the
  feature is a prerequisite with no user-visible surface.

The `relation_edge` and `comment` tables exist in the schema with nothing
writing to them. A table is not a feature.

## 2. Three of the seven database views do not exist

Built and working: **table**, **board**, **list**, **gallery**. Missing:
**calendar** (`DB-CAL-0001`), **timeline** (`DB-TIME-0001`), **chart**
(`DB-CHART-0001`).

`ViewType` names `'calendar'`, but nothing renders it — a name in a union is
not a view.

## 3. There is no asset pipeline

The `asset` table exists in the schema and nothing writes to it.

- **No images, no file attachments** (`UI-0006`). Nothing can be uploaded, and
  no content-addressed store exists to put it in.
- **No code block language selection or highlighting** (`UI-0007`). The block
  exists; the language tag is not settable and nothing is highlighted.
- **No equations** (`UI-0008`).
- **No table block** with row and column handles (`UI-0005`), and **no column
  resize handles** in the database table (`UI-0004`).

## 4. One window, one page

- **No tab strip** (`SIDEBAR-0017`) and no multi-window. One page at a time.
- **No workspace switcher in the UI** (`SIDEBAR-0004`). Workspaces exist and
  the CLI can select one, but the sidebar cannot.
- **No deep links** with its own scheme (`SHELL-0007`).
- **No loading placeholder** (`SHELL-0005`); the window is blank until the
  first state arrives.
- **No activity monitor and no database inspector** (`SHELL-0006`).

## 5. Import and export cover Markdown and CSV

Working: Markdown round-trips with what Openfield itself exports, and CSV
becomes a typed database with whole-column type inference.

Missing: HTML, PDF, lossless JSON round-trip, import of any third-party export
archive, and export of assets. The exporter also does not emit front matter or
nested child pages as files.

## 6. Fidelity was measured against screenshots, never against a running reference

The operator supplied the reference's own packaged build, screenshots, slash
command sheets, tutorial video and its keyboard shortcut list. Those were used
to derive behaviour and to check the shell by eye.

The reference **could not be observed running**, and that was never a choice:
its `app.asar` is 13.1 MB with a 1 MB renderer bundle, and the route it serves
is a `client_placeholder` — the real page UI is fetched at runtime. The block
editor's source is not in the artifact, and the Electron fuses block the
inspector route. So the editor itself has never been seen in motion.

Consequence: **every behavioural catalogue entry is still `[HINT]`** — 169 of
172 rows are hypotheses derived from public documentation, not from observation.
Three rows come from the operator's own requirements. None of the hypotheses
has been verified against the running product, because there was nothing to
verify against.

## 7. Visual fidelity is asserted, not measured

There is no golden-image diff harness, no deterministic rendering mode and no
fixed-clock rendering, so "looks the same" is a judgement made by eye against
`analysis/ref/`, not a number.

The app's screenshots are generated by the app's own harness into `docs/images/`
and can be compared against `analysis/ref/block-types.png` and
`analysis/ref/database-screenshot.png` directly.

Light is the default theme and the reference frame is dark. That is a
deliberate divergence on the operator's instruction, not an oversight.

## 8. Text entry is not IME-complete

`A11Y-0004`: composition events are not handled. Text composed by an IME —
Chinese, Japanese, Korean, and several others — is not committed correctly.

The pending-text mechanism added to stop dropped keystrokes does not cover
composition, because a composition is a single in-flight sequence rather than a
sequence of keystrokes. This is the most likely way the editor still feels
wrong to a real user.

## 9. The shipped application icon is the reference product's mark

This breaks clean-room rules 2 and 3 in `PROMPT.md` section 2, and the brief
names this exact look as the thing to avoid. **It must be replaced with
original artwork before the project is published.**

It is tracked in the vault's checklist under release gates rather than in the
ledger, because the ledger tracks features and this is compliance.

## 10. Smaller known items

- **Keybinding mappings are guesses.** `ctrl+shift+s` for strikethrough,
  `ctrl+e` for inline code and `ctrl+p` for quick find are plausible but
  unverified, and the mapping table is exactly where a wrong guess does the
  most damage. They are flagged `HINT` and should not be trusted.
- **No shortcut customisation** (`SETTINGS-0007`).
- **No in-page find** (`SEARCH-0007`). Quick find searches pages; it does not
  search within the open one.
- **No emoji picker** (`INLINE-0013`).
- **No visual diff between versions** (`HIST-0022`). Versions are saved,
  listed and restorable; two versions cannot be compared.
- **The installer has no shortcut-creation options** (`PKG-0002`). The NSIS
  wizard shows the licence page and asks for a directory; it creates the
  shortcuts unconditionally.
- **The page title is not the first block** (`PAGE-0001`). It is a separate
  field with its own editor, not a block in the document flow.
- **No trash retention policy** (`TRASH-0004`). Nothing is purged, and no
  unreferenced asset is collected.
- **No MCP server and no JSON control channel** (`AGENT-0006`, `AGENT-0007`).
  The CLI is the agent interface so far.
- **`pnpm` is not installed on this machine**, so the workspace uses npm
  workspaces rather than pnpm. `AGENTS.md` and this file were updated to match.
- **Numbered lists renumber by CSS counter over the whole page**, so a nested
  numbered list continues counting rather than restarting per contiguous run.

## 11. What is genuinely solid

Worth stating plainly, because the list above is long:

- **308 unit and scenario tests and 74 end-to-end tests pass**, and `tsc -b` is
  clean. The end-to-end tests drive the real packaged application.
- The document model, transactions and undo are covered by a 300-operation
  randomised edit sequence that must return to the exact starting tree after
  full undo and reproduce it exactly after redo.
- Undo correctness is enforced structurally: every transaction asserts the tree
  is valid before it is recorded.
- Fractional ordering is verified against an exact BigInt reference, with
  regression tests for the two real bugs found while writing it.
- Persistence round-trips a 200-sibling page and survives a simulated restart.
  Crash recovery is proven by a scenario test, not just designed.
- Search ranking, the recent-open boost, literal handling of punctuation, and
  exclusion of trashed pages are each tested individually.
- Every command is reachable through one registry, and the scenario tests drive
  the product only through command ids, so no test depends on private internals.
- The layering and attribution checks are real: injecting a bad import makes
  `layering` exit 1 with the file and line.

## A keystroke can be dropped -- fixed

**Severity was: wrong-behaviour. Not data loss -- the character never reached the
model, so nothing was saved wrongly -- but the user lost what they typed.**

Seen in `tests/e2e/desktop-editor.spec.ts`: typing `Hello Openfield` produced
`Helo Openfield`. One character vanished.

**Why.** The block's text is controlled by React and comes from the model. Every
keystroke goes: `onInput` -> `block.setText` -> the session -> the model -> a
state push -> a re-render that writes the model's text back into the
contenteditable. A character typed *while* the first round-trip was still in
flight was overwritten by that write, because the write used the model's text and
the model did not yet have the second character.

There were **two** writers, not one, and fixing only one is what made this look
like a flake for a long time:

1. **React's commit.** The block's children are rendered from the model. When
   the model lagged, React wrote its text over the DOM's.
2. **A layout effect.** `syncText` wrote `el.textContent = row.text` on every
   state push. That one bypassed React entirely, so a local buffer in React
   could not stop it.

**The fix.** The editor keeps the text the user has typed -- the *pending text*
-- and treats the DOM as the copy that holds the character:

- The pending text is what React renders for that block, so React's commit
  writes back exactly what was typed.
- `syncText` refuses to write the model over a block whose pending text
  disagrees with the model: the model is behind, and the DOM is the only copy
  that has the character.
- The pending text is dropped when the model catches up. `run` resolves *after*
  the state push, so a resolved `block.setText` means the model has the text.
- Every command other than typing clears it, because for those the model is
  authoritative. Undo is the case that matters: it moves the model backwards, to
  text the user did not just type.

**The second bug was hiding behind the first.** Dropping the pending text
re-renders the block from the model's runs, which replaces the element's
children, and replacing children collapses the selection into the element. The
caret-restoring layout effect did not re-run, because its dependencies had not
changed, so the caret stayed at the start of the block and the rest of the word
was typed there: `Hello Openfield` arrived as `lo OpenfieldHel`.

**How it is guarded now.** `tests/e2e/editor-typing.spec.ts` types fast and
checks both the screen and the model. The undo test in `desktop-editor.spec.ts`
failed six times out of six before the fix and passes now -- the caret bug had
been corrupting the model's text, not just the display.
