# Charter — Openfield

## Mission

Build a free, open-source, local-first workspace application — nested pages, a
block editor, and page-backed databases — whose *interaction model*, *keyboard
model*, *data model*, *layout logic* and *visual rhythm* are close enough to the
best-known commercial workspace tools that an experienced user is not surprised
by anything, while every line of code, icon, illustration, word and name is
original or openly licensed.

Not a byte-for-byte replica. A faithful behavioural rebuild, written clean-room.

## Method

1. **Clean-room.** Study behaviour and interfaces, never copy code or assets.
   Recovered material is treated as a *specification of observable behaviour*
   and rewritten in our own words.
2. **Everything is a command.** One registry with stable ids drives the UI,
   keyboard shortcuts, command search, a CLI, a JSON control channel and an MCP
   server. This is what makes the product testable and agent-drivable.
3. **Honest parity accounting.** A ledger of every catalogued feature with a
   status and a proof path. `DONE` without proof is forbidden. Percentages are
   generated from the ledger, never estimated.
4. **Self-rendered evidence.** The app's own harness produces the screenshots
   that back every visual claim.
5. **Layering enforced by tooling.** Lower layers never import higher layers;
   CI fails on violation.
6. **One CI command** runs format, lint, typecheck, unit tests, layering,
   attribution and build.

## Legal rules (non-negotiable)

1. Do not copy another product's code. Analysis informs behaviour; all code is
   our own.
2. Do not copy another product's assets: no logos, wordmarks, app icons,
   illustrations, template galleries, emoji artwork, icon files, bundled fonts,
   sounds or distinctive long UI strings. Short functional labels ("Search",
   "Trash", "Favorites") are ordinary words and are fine.
3. Never use another vendor's name or marks in our name, title, installer,
   package id, URL or bundle id.
4. No service impersonation. Never contact a vendor's servers from the product.
   Never reuse another product's tokens, cookies, session state or private
   endpoints. The product runs fully offline. Third-party compatibility, if any,
   is implemented from **export files the user supplies** and **public
   documented formats**.
5. No circumvention of licensing, authentication, DRM, signing, update or
   integrity checks. No patching of third-party binaries. No redistribution of
   them.
6. Privacy. Never read, copy, log or ship real personal account data. Use
   synthetic samples for every test.
7. Dependencies must be MIT, BSD, ISC, Apache-2.0, or MPL-2.0 as an unmodified
   dependency. No GPL, AGPL or commercial licence is linked in. Every
   dependency is recorded in `THIRD_PARTY_NOTICES.md`.
8. If an instruction would force us to break rules 1–7: stop, explain, offer the
   clean-room alternative.

## Fidelity contract

Fidelity is judged on eight axes, in priority order:

1. **Interaction model** — what a click, drag, hover, focus, selection and
   keystroke does. Highest priority.
2. **Keyboard model** — every shortcut and every Enter/Backspace/Tab/Esc rule in
   every block type.
3. **Data model** — blocks are typed nodes in a tree with stable ids; pages are
   blocks; databases are typed collections of pages with views.
4. **Layout logic** — sidebar structure, page width modes, title area,
   properties area, content column, margins, scroll, hover affordances, and
   where menus anchor relative to the caret.
5. **Visual rhythm** — type scale, line heights, spacing, colours for light and
   dark, radii, shadows, icon size, hover and selected colours. Measured
   numerically, not guessed.
6. **Motion and feedback** — transition durations and easings, drag
   indicators, toasts, skeletons.
7. **Feature breadth** — percent implemented per area, in the ledger.
8. **Interoperability** — Markdown, HTML, CSV, JSON and PDF in and out.

Fidelity is *not* judged on: brand identity, cloud collaboration, AI features
that call hosted services, calendar or mail products, or enterprise
administration. See `docs/gaps.md`.

## Out of scope

Anything requiring another vendor's servers; their branding, assets or
marketplace; real-time hosted features we have no infrastructure for. Deferred
architecture hooks only: multi-user sync, permissions, guests, mobile, meeting
capture, SSO, analytics.

## Definition of done (per slice)

1. Code merged; typecheck, lint and unit tests green.
2. Ledger rows updated with a proof path that exists.
3. At least one end-to-end or headless scenario passes through the agent
   interface, and where UI is involved a Playwright test passes.
4. A screenshot generated by the app's own harness is saved.
5. `STATE.md` updated; commit made.
6. No new warning-level logs in the standard scenario.

## Honesty

Use these four words precisely:

- **implemented** — code exists and compiles.
- **working** — it was run and the result seen.
- **tested** — an automated test exists and was seen passing.
- **verified against the reference** — compared with observed or documented
  behaviour.

Never claim "all tests pass" without running the suite in the same session and
quoting the summary line. Never write "the installer works" without having
installed it, or without saying plainly that it was only built. Show failing
output when something fails. A false "done" is the worst thing we can produce.
